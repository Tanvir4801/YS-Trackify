## Change 15 — Firestore data is NEVER touched by deployment

Confirm to the agent: Vercel deployment only updates the 
React/Next.js website code. It does NOT touch Firestore.
Firestore data lives independently in Firebase cloud.
A new deployment CANNOT delete or change Firestore data.
The only way to change data is via the app/admin panel UI.

=============================================================
SUMMARY OF ALL STATUS RULES
=============================================================

After these changes, the full status logic is:

| Status  | Counts | In wage | Shows at sites | Can change to |
|---------|--------|---------|----------------|---------------|
| present | ✓      | Full    | Only that site | A, H, Pending |
| absent  | ✓      | Zero    | Only that site | P, H, Pending |
| half    | ✓      | Half    | Only that site | P, A, Pending |
| pending | ✗      | Zero    | ALL sites      | P, A, H       |
| (none)  | ✗      | Zero    | ALL sites      | P, A, H       |

"pending" and "no record" behave identically for the labour 
pool. The difference is "pending" has a Firestore record 
(so admin can see it was reset), while "none" has no record.
